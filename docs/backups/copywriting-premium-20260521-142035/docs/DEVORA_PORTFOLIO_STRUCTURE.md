# DevOra Portfolio Structure

## Principe

Le portfolio public n'est pas un dump de projets. Il presente les produits
DevOra comme preuves fonctionnelles sans exposer les sources.

## Structure recommandee

Chaque produit doit avoir :

- nom public coherent ;
- statut ;
- contexte ;
- probleme ;
- solution ;
- valeur business ;
- fonctionnalites ;
- stack ;
- captures reelles validees ;
- CTA de contact ou early access.

Pour DevOra Sentinel, la fiche publique doit aussi mentionner :

- Early Access limite a 50 personnes ;
- 1 mois inclus ;
- activation manuelle par email ;
- compatibilite cible `PC x64 2020+` ;
- mode leger pour machines modestes ;
- option theme personnalise avec couleurs precises fournies par le client ;
- aucune promesse sur PC anciens, OS obsoletes ou IA locale lourde sans ressources adaptees.

## Captures

Maximum recommande : 2 a 3 captures par produit.

Captures creees :

- DevOra Atlas Commerce OS : dashboard, analytics.
- FluxPilot AI : dashboard, workflows.

Captures a reprendre :

- DevOra Sentinel : cockpit avec API visible.
- DevOra Command Center : dashboard apres session demo.
- DevOra Commerce OS : apres restauration dependances.

## Confidentialite

Ils ne doivent pas etre ajoutes a GitHub depuis le site vitrine.
